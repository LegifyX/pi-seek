## Hard requirement (from the maintainer)

**pi-seek must work fully standalone with `pi -ne`** — no other extension may
be required at runtime. Consequences enforced by every plan:

- Never add runtime dependencies to `package.json`. At runtime the extension
  resolves `@earendil-works/pi-coding-agent`, `@earendil-works/pi-tui`, and
  `typebox` from the pi installation itself (the extension loader aliases them).
- DevDependencies (typecheck/test tooling) are fine — they never ship.
- Nothing may assume pi-chimera or any other extension exists.
- Plan 007 verifies standalone operation explicitly.

## Findings considered and rejected

- Security category: **no findings** — API key flows env → models.json →
  in-memory cache, never logged or echoed in error messages; no injection
  surfaces found (all request bodies are JSON.stringify'd).
- `Type.Optional` handling in `toStrictSchema`: refuted empirically — typebox
  1.3.7 encodes `Optional` transparently (no anyOf/null wrapper), so optional
  fields convert correctly to strict-required fields.
- `mapResponsesUsage` fallback total missing `cacheWrite`: negligible — the API
  always sends `total_tokens`.
- Full-history replay per `ds_chat` round: by design (stateless Responses API),
  documented in README.
- Missing runtime deps in package.json: by design — the extension loader's jiti
  aliases resolve them from the pi install.
- Single-file layout: deliberate, documented in the file header. Plans keep it.
- `before_provider_request` handler return-value contract: verified correct
  against pi 0.83.0 (`emitBeforeProviderRequest` uses the return value).
