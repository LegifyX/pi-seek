## Why this matters

The repo currently has **no working verification gate**. The only check
command (`npm exec -- ultracite check`) exits with an error on the committed
`models.json` formatting. There is no typecheck (no tsconfig, no TypeScript
devDependency) and no test runner. Every other plan in this series needs
machine-checkable gates to prove its work; without this baseline, none of
them can verify anything. This plan makes `check`, `typecheck`, and `test`
all exit 0 — the prerequisite for everything else.

## Steps

### Step 1: Make the formatter pass

Run `npm exec -- ultracite fix`. It may rewrite `models.json` (key alignment)
and anything else Biome flags.

**Verify**: `npm exec -- ultracite check` → exit 0. Run `npm exec -- ultracite check`
a second time → still exit 0 (idempotent).

### Step 2: Add devDependencies

Edit `package.json` `devDependencies` to add (keep existing entries):

```json
"@earendil-works/pi-coding-agent": "0.83.0",
"@earendil-works/pi-tui": "0.83.0",
"@types/node": "^22",
"typebox": "1.3.7",
"typescript": "^5.9.0"
```

Pin the three pi-provided packages **exactly** (no `^`) so the types match
the running pi. Run `npm install`.

**Verify**: exit 0; `package-lock.json` updated;
`ls node_modules/typebox node_modules/@earendil-works/pi-tui` → both exist.

### Step 3: Create tsconfig.json

```jsonc
{
  "compilerOptions": {
    "target": "ES2023",
    "module": "NodeNext",
    "moduleResolution": "NodeNext",
    "strict": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["deepseek-v4.ts", "tests"]
}
```

Notes: `allowImportingTsExtensions` requires `noEmit` (satisfied). Node's test
runner executes `.ts` files via native type stripping, so tests import
`../deepseek-v4.ts` with the explicit extension.

### Step 4: Add scripts

Add to `package.json` `scripts`:

```json
"test": "node --test tests/",
"typecheck": "tsc --noEmit"
```

### Step 5: Create the smoke test

Create `tests/smoke.test.ts`:

```ts
import { test } from "node:test";
import assert from "node:assert/strict";
import extension from "../deepseek-v4.ts";

test("extension module loads and exports a default factory", () => {
  assert.equal(typeof extension, "function");
});
```

This proves the module (including the `Type.Object(...)` tool-parameter
definitions at load time) imports cleanly against the devDependencies.

**Verify**: `npm test` → exit 0, `tests 1` / `pass 1` (Node's TAP-style
summary).

Troubleshooting: if `node --test tests/` does not discover `.ts` files on
your Node version, run `node --test tests/smoke.test.ts` explicitly and
continue (report the discovery issue in your final summary).

### Step 6: Typecheck the extension

Run `npm run typecheck`. If pre-existing type errors appear in
`deepseek-v4.ts`, fix them minimally, matching the surrounding code style.
Expected result: 0 errors.

**Verify**: `npm run typecheck` → exit 0, no output.

STOP condition note: if a type error comes from the pi API types themselves
(pi 0.83.0's declared signatures contradicting how the extension uses them),
do NOT contort the code — report with the error text instead.

### Step 7: Final gates

Run all four, in order:

1. `npm run typecheck` → exit 0
2. `npm test` → exit 0, smoke test passes
3. `npm exec -- ultracite check` → exit 0
4. `npm exec -- ultracite fix` → exit 0 and reports nothing to change
   (idempotence)
